# 同类手术软件日志分析工具：构建说明

本文是给**另一名代理 / 开发者**的任务书：为**另一款手术机器人软件**做一套与 [TomasDo/log-tool-tka](https://github.com/TomasDo/log-tool-tka) **同架构、同交互**的本地日志分析工具。参考仓库分析的是 Titan（TKA）产品；新产品的页面、步骤、日志句、手术身份键都不同。

**要抄的：** 参考仓库的产品形态、目录、Python 服务、前端布局、匹配引擎结构、时间轴轨道、方案汇总卡片、git 纪律。

**不要抄的：** Titan 的匹配串、步骤中文名、页面名、uuid 字段名、必要步骤清单。那些只属于 Titan。新产品的字符串必须从**真实日志**和用户给出的层级表里提取，写进新产品自己的 spec。下文若举 Titan 例子，只说明「参考仓库怎么实现这类规则」，**不得当作新产品的匹配串或步骤名照抄**。

关键文件（参考仓库，复制结构不要复制业务常量）：

| 文件 | 职责 |
| --- | --- |
| `app/parser.py` | 按行解析 logger；崩溃非标准行收成一块；分类入口 |
| `app/spec.py` | 读 markdown 表 → 匹配规则；mtime 热加载 |
| `app/nle.py` | 页面层级轨道、会话/手术合并、方案汇总、实测−方案 Δ |
| `app/main.py` | 标准库 `http.server`，默认 `0.0.0.0:8765` |
| `app/store.py` | 导入副本与 `data/index.json` |
| `web/` | 无构建步骤的静态页（`index.html` / `app.js` / `style.css`） |

分类规则只来自 **spec markdown**。改表保存后点「重新加载规则」或刷新页面即可（服务按文件 mtime 自动重载）。**层级、汇总、Δ 比较写在 `nle.py`**，改那些要动代码并同步 spec。

提交身份固定为 `TomasDo <TomasDo@users.noreply.github.com>`，用环境变量传入 `GIT_AUTHOR_*` / `GIT_COMMITTER_*`。**永远不要 `git config`。** 医院现场日志、`samples/`、`data/` 永不进 git。

## 1. 先向用户要齐

动手写匹配表或代码之前，向用户一次要齐下面清单。缺哪项就问哪项；**不要用 Titan 的步骤名去猜新产品。** 显示名一律中文。

1. **真实日志 ≥ 10 份**  
   覆盖：完整手术、多次启动同一台、空启动（没打开方案）、崩溃、设备断连、规划未开始。医院改名文件也要几份。不要用合成日志当主依据。

2. **页面层级**  
   一级 / 二级 / 三级 / 设备 各自有哪些中文显示名。哪一级是顶栏大页面，哪一级是页内任务清单，哪一级是附加采集，哪些后台状态进**设备**轨道（不要画成手术 L1/L3）。容器型主窗口如果不单独占轨道，写明。

3. **匹配串**  
   每条层级、步骤、关键信息、异常、噪声对应的**真实日志子串**（或前缀 / 正则）。从日志里抄，不要发明。源码拼写错误也原样保留（参考仓库里版本字段就拼错了，匹配仍用错拼）。

4. **手术身份键**  
   用什么把「同一台手术」跨多次软件启动拼起来：方案 uuid，或该产品等价物（病例 id、plan id 等）。写清出现在哪一句日志、如何截取。没有稳定键就停下来问，不要用文件名或患者姓名冒充。

5. **必要步骤 + 完成证据**  
   每步：中文名、所属阶段（术前 / 规划窗 / 术中）、**完成证据是哪一句日志**。若完成条件是日志里的**点号 / 序号**（参考实现：出现 `point 5` 即完成），用索引判定，**不要对 1..N 去重计数，不要显示 3/5**。列出「任一即完成」的备选句。

6. **数值规则（两类，不要混）**  
   - **误差幅值**：配准 / 点校验这类「消息最后一个数字就是误差」。超过阈值（常见 >1 mm）升为异常。这才写进 spec 的「阈值」列。  
   - **方案 vs 实测 Δ**：术中采集对照**同一次会话里最近一次方案目标**。|Δ| >1 标重点（key / 金），>2 标异常（红）。**不要**对方案原始深度/角度套阈值（9 mm 截骨量本身不是错误）。

7. **新仓库名**  
   独立 GitHub 仓库（不要写进 Titan 仓库）。确认仓库 URL / 本地目录名、产品中文名、界面标题。

还要顺带确认：日志行格式（时间 / logger / 级别字母 / 线程）、两种文件名（按日滚动 vs 医院改名）、时区、启动句 / 退出句 / 开始手术句、光学定位失败句、机械臂断连句。

## 2. 产品形态（照参考仓库抄 UX）

Python **3.10+**，只用标准库 `http.server`，无需 pip。启动：

```bash
python3 -m app.main
```

默认绑定 `0.0.0.0:8765`（浏览器 `http://127.0.0.1:8765`）。可选 `python3 -m app.main 8765` 或 `python3 -m app.main 0.0.0.0:8765`。`requirements.txt` 标明标准库即可，不要做成必须装 FastAPI 才能跑。

### 布局

- **左侧栏**：产品名、导入日志（多选）、文件列表、底部「重新加载规则」。一次只查看一个文件。删除只删 `data/` 副本，不改原始文件。
- **顶栏**：文件名 + 计数（总行 / 重点 / 异常 / 噪声 / 已显示 等）。
- **工具条**：`显示噪声`、`显示全部`。默认隐藏噪声和未映射行。金色 = 重点（key），红色 = 异常（anomaly 或级别 E/C）。
- **短终端**：默认高度约 **110px**（最小约 64px），等宽字体，显示原始日志。
- **分割条**：只改 **TERMINAL 高度**，不要去改 NLE 的 flex 把时间轴挤没。参考实现是给 `#term-wrap` 设 `flex: 0 0 ${h}px`。
- **NLE 主窗**（时间轴）：X 轴是**日志行号**，不是墙钟。方案汇总卡片在 **NLE 窗底部**（时间轴画布下面），不要放到终端上面或页面最外层底部。

### 轨道（中文标签固定用这些，内容按新产品填）

从上到下：

1. **手术** — 同一身份键一台手术；多次启动色块不断开，内竖线切「第 n 次」
2. **日志** — 全文，一行一个刻度
3. **一级** — 大页面
4. **二级** — 当前一级下的任务清单
5. **三级** — 页内附加采集等
6. **设备** — 维护 / 相机 / 示踪器 / 定位设备等后台，不是手术 L1

### 交互

- **缩放只用按钮**（− / + / 适应窗口）。拖动和滚轮只**平移**，不要当缩放。
- 点击轨道或事件 → 播放头跳到该行，终端跟着滚。
- 悬停验证块显示 **目标 / 实测 / Δ**（有单位）。
- 启动、版本用 `pin` 旗标钉在标尺和手术轨道上；版本徽章归该次启动。终端里这两行单独高亮。
- 深色中文 UI（参考 `web/style.css` 的色板与 CJK 字体栈）。

### 方案汇总

- **每个手术身份键一张卡片**。点卡片跳到该手术。
- **只有点过「开始手术」（或该产品等价句）的才评估必要步骤。**
- 已加载方案但未开始：卡片显示「未开始手术」，**不要把每步标成全红未做**。
- 空启动（没打开方案 / 没有身份键）：**不出卡片**；手术轨道上可以是灰色空块，不要并入任何手术。
- 未打开方案的会话不要全部标红。

本地 API 与参考仓库对齐即可：`GET/POST /api/logs`、`POST /api/logs/import-path`、`GET /api/logs/{id}/timeline?show_noise=&show_all=&center=&window=`、`DELETE /api/logs/{id}`、`GET /api/spec`、`POST /api/spec/reload`。事件 >5 万时默认过滤集 + `truncated`。

## 3. 新仓库怎么铺（独立仓库，不是本仓库）

在**新产品自己的空仓库**里建，不要往 `log-tool-tka` 里加第二套产品。建议布局：

```
README.md
.gitignore          # 必须忽略 samples/、data/、__pycache__/、.venv/
requirements.txt    # 注明只用标准库
docs/<产品>-log-spec.md
docs/page-hierarchy.md
app/__init__.py
app/parser.py
app/spec.py
app/nle.py
app/main.py
app/store.py
web/index.html
web/app.js
web/style.css
data/               # 导入副本，gitignore
samples/            # 本地试跑，gitignore
```

可以从参考仓库复制 `app/` 与 `web/` 当骨架，然后：

- 改产品名、标题、logger 正则、启动/退出/开始手术等**生命周期句**（这些必须换成新产品日志里的原文）。
- 换掉 `nle.py` 里所有层级匹配、CUT_MAP、必要步骤短语。**清空 Titan 常量，换成用户提供的串。**
- 重写两份 markdown。spec 是唯一分类配置；hierarchy 只定 L1/L2/L3/设备以及手术/会话怎么画。

### 匹配顺序（硬编码，与 spec 文内约定一致）

1. 级别 **E/C**（含空的 `---E---`，标签「空错误行」）
2. **异常表**
3. **噪声表**（默认隐藏；若同时标 anomaly 仍显示）
4. **步骤映射表 + 关键信息表**（同一张表从上到下，第一条命中即停）
5. **未匹配**的已解析行：默认隐藏，「显示全部」才出现

不要解析「软件页面与步骤（业务顺序）」那张表（列是顺序/源码页面，不是日志匹配）。

### Spec 表列

步骤 / 异常 / 噪声表：

`日志匹配 | 匹配方式 | 软件步骤 | 类别 | 时间轴 | 标注 | 说明`

关键信息表多一列 **阈值**（或 `threshold`）。

- 匹配方式：`contains`（默认）| `prefix` | `regex`
- 类别：`lifecycle` / `page` / `step` / `key` / `robot` / `noise` / `other`
- 时间轴：`show` | `hide`
- 标注：`none` | `key` | `anomaly` | `pin`

**「阈值」列只用于误差幅值**（配准误差、点校验误差：取消息最后一个浮点数，超过则升 anomaly，事件带 `value_mm`）。**截骨深度、方案角度、术中 collect-check 的原始读数不要填阈值**——那些走 `nle.py` 的 |实测−方案|。否则 9 mm 计划深度会被当成超限。

级别：E/C → anomaly 且显示；W 默认显示但不升异常；I/D/T 由映射表决定。

## 4. 实现模板（模式，不是 Titan 步骤名）

下列是参考仓库已经验证过的**规则类型**。新产品用自己的身份键、自己的日志句填空。括号里的英文/中文例子来自参考实现，**禁止原样写进新产品 spec。**

### 会话 vs 手术

| 单位 | 切分 | 合并 |
| --- | --- | --- |
| 会话 session | 启动句 → 下一次退出或下一次启动 | 一次进程寿命 |
| 手术 case | 加载方案句里的身份键 | **相同键的多个会话合成一台手术**，即使中间隔了另一台 |
| 未打开方案 | 会话里没有身份键 | 灰块画在手术轨道，不并入任何手术 |

标签用方案品牌/型号 + 手术侧这类非姓名字段。不要把患者姓名写进轨道。

启动清空「当前方案快照」；方案被编辑会再打目标参数句，Δ 始终用**本会话最近一次**快照。

### 必要步骤的四种类型（按用户清单实例化）

1. **术前采集**  
   行范围内出现任一约定证据句即完成（参考：标记钉采集看 widget-open / verify-error 等任一）。不要要求「全套证据都出现」。

2. **配准 / 点校验（按索引）**  
   完成条件是日志里的点号 N（参考：出现 point 5）。**不要计数、不要显示 3/5。** 悬停可列出出现过的点号。没有该点号 = 未做完。

3. **规划窗采集**  
   只统计规划时间窗：进入「规划/截前」之后，到「截后」或首次术中截骨之前。窗口外的同名采集（术后间隙等）**不算**规划完成。若只有术后采集，明细写「仅术后采集」而不是笼统「未做」。

4. **术中实测 vs 最近方案（collect-check）**  
   每个要求采集的参数：有实测句才算采集。缺的标 **「未采集」**。进入对应验证步（或只做了截骨未进验证）但缺实测 → 在该二级块上标「未采集」；只截骨未验证时，未采集挂在**截骨块**上；未做到截骨也未进验证的会话，该面不标未采集（汇总里仍可按「已开始的手术」记未做，这是汇总规则，不是轨道块标注）。

### 数值

- 误差幅值：spec 阈值列，常见 >1 mm → anomaly。
- |实测 − 方案|：**>1** 标 key（金），**>2** 标 anomaly（红）；|Δ| ≤ 1 不加额外标记。长度 mm、角度 deg 同一套 1/2。
- 比较在 `nle.py` 做，不要对 collect-check / plan 原始数字套阈值列。

### 容易混的日志（参考仓库踩过，新产品对号入座）

- **机器人位姿 / 导板到位后的关节或平面数 ≠ 验证工具采集。** 那些进噪声或隐藏，不要拿来当实测、不要算 Δ。
- **光学定位连接失败 = 异常**（参考：NDI fail）。进模拟器也算异常，除非用户明确说该机型没有该硬件。
- **机械臂 / 控制器断开：仅「开始手术」之后、返回方案管理或退出之前**标异常；非术中断开隐藏或降为普通。把「开始手术」换成该产品的等价句。

台车/设备放置若有左右：默认同侧不显示，与手术侧不一致才标记。示教按下/松开、机械臂停止要能落到时间（行号）。

## 5. 日志现实与工程细节

- **两种文件名：** 按日滚动（如 `log_file_YYYY-MM-DD.txt`，从文件名取日期）以及医院改名（`医院-病例-姓名-侧-后缀.txt`，内容格式相同，日期用 mtime 或显示未知）。两种都要能导入。
- **崩溃非标准行：** `CRASH DETECTED`、`Caught signal`、堆栈等对不齐 logger 正则的行，收成一条异常事件（block），不要丢。
- **保留源码拼写错误：** 匹配串必须和日志原文一致。不要在匹配列「修正」成正确英文。显示名可以用正确中文。
- **大文件窗口化终端：** 参考 `nle.py`：全文行数很大时（约 >8 万行）终端只返回播放头附近窗口（默认约 1.2 万行），带 `lines_windowed` / `lines_start` / `lines_end`；时间轴 ticks 仍覆盖全文。点远处行再按 `center` 拉窗口。
- **改规则 vs 改代码：** 只改 spec 表 → 刷新页面或点「重新加载规则」（JS 再请求即可）。改 `nle.py` / parser / 前端 → **重启 Python 进程**。文档里写清楚，避免代理改了后端还以为刷新就生效。

解析时 UTF-8、`errors="replace"`。qDebug / 只打 stdout 的行若根本不进日志文件，不要假装能解析。

## 7. 不要做的事

- **不要把新产品混进 Titan 仓库。** 本仓库 `log-tool-tka` 只服务 Titan。新产品开独立 repo。
- **不要去克隆手术软件的 C++/Qt 应用**来「对照源码猜日志」。以用户提供的层级表和真实日志为准；源码枚举名最多当注释，不能代替匹配串。
- **不要发明匹配串。** 日志里没出现过的句子不要写进 spec。不确定就列入「先向用户要齐」，不要脑补。
- **不要对方案原始数字套阈值。** 阈值只判断误差幅值。截骨量 8 mm、9 mm 不是异常。
- **不要把规划采集和术后采集混成一步。** 规划只看规划窗；术后 collect-check 走 Δ / 未采集。
- **不要在低优先级问题上卡住。** 颜色微调、图标、非阻塞的文案可以先按参考仓库做，把匹配、层级、汇总、Δ 做对。缺关键输入（身份键、完成证据、真实日志）时问用户，不要用 Titan 步骤名顶上。
